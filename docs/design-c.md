## 1. 画面構成（丸型ウォッチ基準）— レイアウト v0.2（2026-11-11 ユーザー指定で改訂）

```
             ╭───── 12時マーカー ─────╮
        左クリック弧（120°） │ 右クリック弧（120°）   ← 外周リング層（下レイヤー）
      ╱        ┌─────────────┐        ╲
     │         │  ▲ リング     │         │
     │         │◀ ( ◎ ノブ ) ▶ │         │   ← 中央ハイブリッド 直径65%（上レイヤー）
     │         │  ▼           │         │
      ╲        └─────────────┘        ╱
        ● LOCAL │ イベント表示 │ スクロール   ← 下部弧（120°）
```

- レイヤー構造: 中央ハイブリッド（③）が上レイヤー、その周囲の円弧セクター（①）が下レイヤー
- ③ 中央ハイブリッド: 画面中央に配置し、直径は画面直径の **65%**（v0.2の75%から縮小、2026-11-11）
- ① クリックボタン: ③の外側の輪（内径約68%〜外径約90%）を3等分した **120°ずつの円弧セクター**
  - 左上120°＝左クリック、右上120°＝右クリック、下120°＝情報ゾーン（②）
  - **①のタッチ判定は、③に覆われていない部分だけ**（判定は③を先に見る）
  - ラベルは円弧に沿う接線方向の文字で置く
- ② イベント表示: 下部セクター中央に移設。左下に接続表示（LOCAL）、右下にスクロール切替も同セクター内
- テストパネルは下部セクターの長押し（0.6秒）で開く（右半分は短タップ＝スクロール切替、長押しはパネル優先）
- デザイン方針（0.3、2026-11-11 ユーザー指定）: **派手すぎず、機械的で未来感**。
  レーダー文字盤は実装の基盤（基板）としてのみ使い、デザインは引っ張られない
  （緑グリッド・黄色・赤三角は廃止）
  - 基調: グラファイト黒 #2B2F34 → #0B0C0E の放射グラデーション
  - ライン: スチールグレー #7D858D、文字 #D5DBE0
  - アクセント: くすみシアン #7FD4E8 を最小限（中心点、接続ドット、12時ノッチ、
    押下時の薄い点灯のみ。常時発光はしない）
  - ボタン面の塗り（2026-11-11 ユーザー指定）: 背景はグラファイトのまま、
    ボタンは塗りつぶしにする。左クリック＝濃いグレー緑 #26302A（枠 #8AA892）、
    右クリック＝濃いグレー青 #26303D（枠 #8AA2B8）、
    十字パッド＝少しだけ明るい黒 #24272B、下部セクター＝#1F2225
  - 計器感の要素: 二重目盛りリング、同心円ヘアライン、隙間のあるセグメント分割、
    ノブ外周のローレット表現、英字マイクロラベル（BTN-L / SYS.UI-03 等）
- 左クリックは主ボタンとしてアクセント枠、右クリックはグレー枠で一段落とす
- スマホ版は同じ配置のまま拡大する（指の記憶を共通にするため）

※ v0.1 の旧レイアウト（上部に四角ボタン約25%／中央約50%／下部バー約20%）は廃止。
※ 実装状況: プロトタイプAPK 0.3（2026-11-11 ビルド済み）に本レイアウト＋0.3デザインを反映済み。
  ボタンの立体感は、落ち影＋上端ハイライト＋上下グラデーションで表現する。

## 2. 中央ハイブリッド操作部

操作部は「外周リング」と「中央ノブ」の2層。触れた場所でモードが決まる。

### 2a. 外周リング ＝ 十字キー（精密移動）
- リングを4つの扇形（上・右・下・左、各90度）に分ける。印は ▲▶▼◀
- タップ: その方向へ **1ステップだけ** 移動する。ステップ量は初期値 12px（設定で変更可）
- 長押し（約350ms〜）: 同方向へ連続リピート。最初はゆっくり、保持が続くと加速する
  （リピート間隔 120ms → 40ms へ段階的に短縮、という決定的な方式にする）
- 斜めの扇形は作らない。斜め移動が要る場合はレバー側でやる、と役割を分ける

### 2b. 中央ノブ ＝ レバー（連続移動）
- ノブ（直径は操作部の約45%）をドラッグして倒す操作
- 倒した方向へポインターが動き、**倒した量で速度が変わる**
  - デッドゾーン: 中心から約8%までは動かない（手ブレ・誤動作防止）
  - 速度曲線: 倒し量の2乗に比例（小さく倒すと極低速、大きく倒すと高速）
  - 最大速度の初期値: 約 1200 px/秒（設定で変更可）
- 指を離すとノブは中央へバネで戻り、移動は即停止する
- 送信は約30回/秒に間引き、`cursor:move {dx, dy, sens}` を送る（旧プロトコル流用）
- ノブを倒している間は、方向を示す小さな矢印／照準をノブの先に表示する
  （文字盤のロックオン照準のモチーフを流用）

### 2c. 判定の優先順位（誤動作を防ぐ決め事）
- タッチ開始点がノブ内 → レバーモードで固定（途中でリングに出てもレバーのまま）
- タッチ開始点がリング上 → 十字モードで固定（ノブ側へ滑っても切り替わらない）
- この「開始点で決めて固定する」方式により、操作途中のモード暴走を防ぐ

## 3. クリックボタン（v0.2: 外周の120°円弧セクター）

| 操作 | 動作 | 送信 |
|---|---|---|
| 左をタップ | 左クリック | `cursor:click {button:"left"}` |
| 左を素早く2回タップ | ダブルクリック | `cursor:click {button:"left", double:true}` |
| 左を長押し（約300ms〜） | ドラッグ開始 | `cursor:down {button:"left"}` → 離して `cursor:up` |
| 右をタップ | 右クリック | `cursor:click {button:"right"}` |
| 右を長押し | （左と同じく）右ドラッグ | `cursor:down/up {button:"right"}` |

- 長押しに入った瞬間に軽いバイブ（ハプティクス）で知らせる。タップだけでは鳴らさない
- ドラッグ中はボタンの表示を「押下中」の黄色ベタ塗りに変える
- ドラッグしながらもう一方の手／指で中央レバーを動かせるよう、
  クリックボタンと操作部はマルチタッチで同時処理する（これが一番の実装上の注意点）

## 4. 下部セクター（120°円弧内、補助・最小限）

- 中央: イベント表示（②。最後の操作内容＋スクロール量など）
- 左下: 接続状態ドット（緑＝接続中、黄＝接続待ち、赤＝未接続）と接続先名／ルームコード `TIC-XXXX`
  （プロトタイプでは「LOCAL」表示のみ）
- 右下: 「スクロール」切替
  - ON の間だけ中央操作部がスクロールモードになる（レバー上下＝`cursor:scroll`、
    リング上下タップ＝1ノッチずつ）。表示は操作部の枠色を変えて明示する
  - もう一度タップすると通常モードへ戻る。モードを増やしすぎないため、切替はこの1つだけ
- 設定（感度・ステップ量）はメイン画面に置かない。下部セクター長押しで開く
  テストパネル／別画面に分離する

## 5. 接続・土台（2026-11-11 接続機器の確認で更新）

接続先は **基本がスマホ（主）、PCにも接続したい（副）**。方式は対象で分ける。

### 5a. PC（＋他人のスマホ／タブレット／TVなど）＝ Bluetooth HID で直接
- ウォッチアプリ自身が Bluetooth HID マウスとして登録する
  （Android API 28+ の `BluetoothHidDevice`、`SUBCLASS1_MOUSE`）
- 相手側にソフトは不要。普通のBluetoothマウスとしてペアリングするだけ
- 実例あり: WowMouse 等が Wear OS 時計を HID マウス化し、Windows／Android 等で動作。
  対応表では TicWatch Pro 5（Wear OS 5+）も対象
- 旧方式（WebSocket＋PC側Python/pyautoguiホスト）は予備として残せるが、本命にしない。
  Wi-Fi同一網と常駐ソフトが要り、スマホ操作先には使えないため

### 5b. 自分のスマホ（時計の相棒スマホ）＝ HID直接は使わない
- **重要**: Wear OS 時計は、相棒スマホに対して HID マウスとして安定接続できないと
  WowMouse 公式が明記している。そのペアリングを強制すると時計が
  工場出荷リセットを求める場合があると警告されているため、絶対にやらない
- 代替ルート: 時計 ⇔ スマホは既存の Wear OS 接続（通常のペアリング回線）で命令を送り、
  **スマホ側に小さな相棒アプリ**を入れ、ユーザー補助（AccessibilityService）で
  タップ／スワイプ等の操作を実行する（同種アプリ WristPilot が採用する方式）
- 代償: スマホ側アプリのインストールと、ユーザー補助の有効化が初回だけ必要。
  Androidのポインター表示は外部マウス接続時と違い、操作は「タップ／スワイプの実行」が中心になる

### 5c. 操作側の土台
- Web版（旧マウス）は動かなかったため使わない。
  ウォッチフェイス側の Wear OS ネイティブ（Compose）プロジェクト構成を土台に、
  新しいアプリモジュールとして作る
- 接続先の切り替えはアプリ内の接続先選択（スマホ相棒経由／HID直接）として持つ。
  C案の画面下部の接続表示は、選択中の接続先名も出すよう拡張する

### 機種確定（2026-11-11）
- 操作側: **TicWatch Pro 5 Enduro**（Snapdragon W5+ Gen 1、Bluetooth 5.2、1.43インチ丸型）
- スマホ（主の接続先）: **Pixel 9a**。同ウォッチの相棒スマホであるため、
  スマホ操作は 5b の相棒アプリ＋ユーザー補助ルートが確定。HID直接は向けない
- PC（副の接続先）: 5a の Bluetooth HID 直接で確定

### Wear OS バージョン確定（2026-11-11、実機確認）
- 実機は **Wear OS 4.0**（＝ Android 13 / API 33 相当）
- 影響と判断:
  - アプリ本体（Compose）: 基盤 radar/ の minSdk 30 のままで動作範囲内。問題なし
  - スマホモード（相棒アプリ＋ユーザー補助）: Wear OS バージョンに依存しない。問題なし
  - HIDモード（PC向け）: 使う `BluetoothHidDevice` API 自体は API 28+ で OS 4.0 でも存在する。
    ただし WowMouse 公式の検証条件は Pro 5 で「Wear OS 5以降」であり、
    **OS 4.0 の Enduro 実機で HID 登録が通るかは未検証**という扱いにする
  - 対策: プロトタイプの最初の工程に「HID登録だけの最小テスト」を入れ、実機で可否を判定する。
    もし通らなければ PC向けは旧方式（WebSocket＋PC側Pythonホスト）にフォールバックする
    （その場合も PC 操作自体は可能で、方法が変わるだけ）
